.gest Industry Benchmark

This benchmark compares .gest and .sgm against concrete industry-like shapes generated from the same numeric samples: MediaPipe-like landmarks, OpenXR-like traces, glTF animation JSON, BVH-like text, ROS-like JSONL, and CSV rows.

This is not a certified exporter shootout. The comparison uses deterministic, industry-like trace shapes generated from the same samples. Existing standards still win for their native jobs: glTF/VRM for assets, OpenXR for live device APIs, MediaPipe for landmark extraction, and ROS bags for broad robotics telemetry.

Where .gest / .sgm Is Better Here

  • SGM bytecode is smaller than compact .gest JSON, MediaPipe-like JSON, OpenXR-like traces, glTF-like JSON, ROS-like JSONL, and CSV rows in every generated scenario.
  • SGM bytecode is smaller than BVH-like text in three of four scenarios; the tiny pose7 microclip is the measured exception.
  • .gest JSON keeps a stronger validation contract than landmark JSON, BVH-like text, OpenXR-like traces, and ROS-like logs.
  • .gest/.sgm preserve a non-semantic execution path, so labels and meanings can stay in sidecar governance systems.
