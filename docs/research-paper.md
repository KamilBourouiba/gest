# .gest: A Non-Semantic Intermediate Representation for Compilable Gesture Motion

## Abstract

Human and machine gesture data is usually stored either as application-specific landmark JSON, animation-centric skeleton formats, or runtime logs coupled to a sensor stack. `.gest` proposes a different layer: a non-semantic intermediate representation for spatial gesture motion that can be validated, transformed, compiled to compact `.sgm` bytecode, decoded for debugging, and replayed on interactive avatars.

This repository is a reproducible research artifact for the current draft. It includes the `.gest` schema, invariant validator, SGM v1 compiler/decoder, external-format importers, multiple generated scenarios, measured byte-size comparisons, MP4 renderers, and a WebGL 3D playback lab.

## Positioning

The core claim is not that `.gest` replaces every existing animation or motion-capture format. The claim is narrower and more useful: `.gest` is an IR layer between capture systems, ML pipelines, robotics/XR runtimes, validation tooling, and low-level gesture bytecode.

The design intentionally separates motion from meaning. A `.gest` file can encode hands, gaze, joints, scalar channels, blendshapes, and latent bundles, but it does not encode natural-language glosses, commands, emotions, diagnoses, or user intent. Those labels belong in separate manifests with their own governance.

## Contributions

1. A schema-backed gesture IR with explicit coordinate space, channel definitions, timeline frames, interpolation hooks, profiles, and non-semantic metadata.
2. A reference validator that combines JSON Schema with domain invariants such as joint payload length, state bounds, direction vector shape, and mutually exclusive dense/blob payloads.
3. SGM v1, a compact bytecode target with shared Python and C constants, plus round-trip decoding tools for debugging.
4. Importers for MediaPipe-like JSON, OpenXR-like JSON, and BVH-like text inputs.
5. A reproducible benchmark suite across XR, robot teleoperation, rehabilitation, and dataset microclip scenarios.
6. Visual artifacts: cinematic MP4 rendering, 2D avatar playback, a dependency-free WebGL 3D breakthrough lab with **in-browser SGM decoding**, and a **Unity 6 mannequin runtime** with native C# SGM decoding ([testgest](https://github.com/KamilBourouiba/testgest)).

## Reference Pipeline

The reference pipeline is:

```text
capture/log/input
  -> importer or native .gest document
  -> schema + invariant validation
  -> .sgm v1 bytecode compilation
  -> bytecode decode/debug dump
  -> lossy .gest recovery
  -> avatar/runtime playback
```

This pipeline is implemented by the CLI tools `gest-import`, `gest-validate`, `gest-compile`, `gest-dump-sgm`, and `gest-sgm-to-gest`, plus the demo scripts under `demo/`.

## Measured Results

The current benchmark uses generated but concrete motion clips. Every scenario is a valid `.gest` document, compiled to `.sgm`, and transformed into comparison baselines from the same numeric samples.

- XR dual-hand arc: `.sgm` is 1,562 bytes, compact `.gest` JSON is 4,679 bytes, landmark JSON baseline is 2,536 bytes.
- Robot teleoperation reach: `.sgm` is 1,211 bytes, compact `.gest` JSON is 3,547 bytes, landmark JSON baseline is 2,123 bytes.
- Rehabilitation symmetry loop: `.sgm` is 3,890 bytes, compact `.gest` JSON is 9,330 bytes, landmark JSON baseline is 6,517 bytes.
- Dataset pose7 microclip: `.sgm` is 1,778 bytes, compact `.gest` JSON is 4,131 bytes, landmark JSON baseline is 2,401 bytes.

These numbers are generated by `demo/comparison_stats.py` and `demo/multi_demos.py`. The reports are written to `docs/comparison-stats.md` and `docs/multi-demo-stats.md`.

An additional industry-facing benchmark is generated by `demo/industry_benchmark.py`. It compares `.sgm` against compact `.gest` JSON, MediaPipe-like landmark JSON, OpenXR-like action trace JSON, glTF animation JSON shape, BVH-like skeleton text, ROS-like JSONL topics, and CSV rows. In the current artifact, `.sgm` is smaller than compact `.gest` JSON, MediaPipe-like JSON, OpenXR-like traces, glTF-like JSON, ROS-like JSONL, and CSV in all four scenarios. It is smaller than BVH-like text in three of four scenarios; the tiny pose7 microclip is the measured exception.

## Interpretation

SGM bytecode is consistently smaller than compact JSON in the current scenarios while keeping runtime-facing structure. Gzipped JSON can be smaller on tiny clips because repeated field names compress very well, but gzip is a transport/archive encoding, not an execution format with an opcode stream and channel table.

The practical split is:

- `.gest` JSON/YAML: authoring, interchange, audits, datasets, review.
- `.sgm`: runtime packaging, streaming, embedded playback, VM/SGPU experiments.
- gzip: transport or archival compression around either representation.

## Why This Can Matter

Gesture systems need a layer that is stricter than raw landmarks and more general than an application animation file. A validated IR enables CI checks, reproducible datasets, privacy boundaries around semantic labels, deterministic runtime packaging, and cross-stack adapters.

The breakthrough direction is to treat gesture motion like code: parse it, validate it, lower it, inspect its bytecode, replay it, and benchmark it.

## Current Limitations

- The benchmark is measured but still small; it should grow to real captured traces and longer clips.
- SGM v1 currently targets a small opcode set focused on articulated joints, state indices, directions, and frame boundaries.
- Compression is deliberately simple; delta coding, quantization, and streaming chunk formats are design targets, not complete production implementations.
- The WebGL avatar is a dependency-free demo rig, not a production retargeting engine.
- The Unity mannequin is a procedural rig driven by the same channels; it demonstrates engine integration, not production retargeting to Humanoid/XR Hands.
- The BVH comparison is a BVH-like text baseline generated from the same samples, not an official DCC exporter.

## Reproducibility

Run the full artifact from the repository root:

```bash
PYTHONPATH=src:. python demo/run_demo.py
PYTHONPATH=src:. python demo/comparison_stats.py
PYTHONPATH=src:. python demo/multi_demos.py
PYTHONPATH=src:. python demo/render_video.py
PYTHONPATH=src:. python demo/render_avatar_video.py
PYTHONPATH=src:. pytest -q
python -m http.server 8000
```

Then open:

```bash
open http://localhost:8000/demo/avatar_3d_viewer.html
```
